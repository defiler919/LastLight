# DARKWELL object memory integration

`ADarkwellObjectMemoryScene` owns the project gray-memory runtime. Its source is an ordinary Actor with `UDarkwellRememberablePropComponent` and `USightWeaveObjectPolicyComponent`; it does not require a Lab map, name, controller or furniture subclass. `ADarkwellMovingPropLabRoom` derives from it and supplies fixture geometry, motion, controls and evidence commands.

1. Create one scene for the observer's object-memory domain. Configure `Memory.bUseSpatialMemory = true` before component BeginPlay so the legacy remembered-prop subsystem does not also present this source. Give it a stable, non-empty identity, mesh primitives and gray appearance parameters.
2. Configure the policy before registering its component. Project defaults remain defaults; each object can independently override reveal mode, confirmation span and history mode. Call `Scene.RegisterRememberable(Memory, Policy)` and check its result. Concurrent live duplicates are rejected. After source destruction, registering the same identity attaches a replacement while preserving the old captured knowledge; replacement content is acquired only on legal observation.
3. The host supplies a legal, revisioned `FDarkwellFogVisualSourceSnapshot` and physical occluder segments. `Fog.ActivateForWorld(Bounds, Source, Segments)` establishes the same analytic CPU coverage and D3D12 coverage target used by the project adapter; it does not need an integration fixture. Update the source with `Fog.UpdateSource(Source)`. Invalid input is not empty evidence.
4. Call `Scene.UpdateMemory(DeltaSeconds, ObserverLocation)` **after** publishing coverage and advancing physical actor transforms. The scene intentionally has no independent Tick; the host controls this ordering. Mark actual motion on the object's policy; do not infer player knowledge from that flag. A hidden stop remains unobserved until fresh legal contact.
5. Actor destruction leaves captured knowledge until legal evidence resolves it. Historical proxies reconstruct from captured meshes, part transforms, pose, tint and UV scale. `SetMemoryAppearance` updates gray appearance; call `NotifyMemoryAppearanceChanged` for authored appearance changes which otherwise retain the same material pointer. Arbitrary material-graph snapshots are outside the current gray material contract.
6. `ResetMemory` is an explicit knowledge reset and presentation release. It restores original material/visibility bindings on surviving ordinary source components and does not destroy those actors. It must not be called as a response to hidden movement. Scene EndPlay releases its resources; source disappearance by itself does not reset knowledge.

The project supplies the existing fixed-reveal, accumulated-memory and cut-cap materials. Their asset paths retain historical `PropLab` names; assets have not been moved or rewritten. The runtime uses their established parameter contract at full spatial density and normal project quality. The current integration manages material slot zero of each registered static-mesh primitive, matching the supported project furniture contract.

SightWeave remains the reusable source/occluder authority, per-object policy, and world-length confirmation layer. The gray knowledge store and renderer remain a DARKWELL backend because they depend on project material semantics. This refactor does not claim that the standalone SightWeave plugin contains the complete DARKWELL gray renderer, and does not change plugin public APIs. `SightWeaveRuntime` is now a public project-module dependency because project public headers expose its types.

`Darkwell.ObjectMemory.OrdinaryHost` creates a transient non-Lab world and six ordinary mesh Actors. It exercises policy coexistence, root-mesh transforms, hidden StationaryOnly movement/stop, destroyed-source knowledge, legal empty evidence, invalid publication and Reset. The same native runtime also runs all existing Lab contracts. Graphical quality is verified separately through the real D3D12/SM6 map replay; native NullRHI tests are not visual acceptance.

No map or binary asset migration is required. Continue the current development branch; these checkpoints are not a new user-accepted stable branch.
